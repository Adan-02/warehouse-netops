# 第一轮：一条采样怎样变成看板上的数字

这一轮先建立你自己的解释。用文字箭头或纸笔都可以，不要求先记住准确术语。第一次凭印象写，不确定处标 `?`；查资料后保留原来的猜测，再写修正和依据。

## 任务一：画出主链路

以当前四台 VM 的仓库现场为对象，回答：温湿度在哪里产生，发给谁，谁保存，办公浏览器又向谁请求？把你认为需要经过的机器、进程或服务用箭头连起来。数据发送和网页请求可以画成两条线。

```text
数据产生：

传输与接收：

保存：

网页请求与显示：
```

知道的地方补上 IP、端口或文件位置；不知道的地方留空。对每个箭头写一句“为什么要经过这里”。

另外标出你认为 OpenWrt、Docker 和广州运维端分别出现在什么位置。若你认为某个角色不在数据主链路上，写出理由。

| 仅停止 Broker |  |  |  |  |

挑一个你最不确定的格子，写出一种能帮助判断的观察。可以先写“看某台机器上的某个状态”，不用急着写命令。

## 任务三：修正地图

提交最初预测后，再根据需要阅读 [接手说明](../HANDOFF.md) 与 [项目设计](../../PROJECT.md)。遇到文件名或术语只记录当前问题所需的部分，不必通读所有源码。

将结果写入本机 `.local/learning/RECORD.md`，也可以直接在聊天中回答。助教先针对你最不确定的一处给提示，由你修正。初始回答与修正都保留，便于看出理解如何变化。

## 这一轮的完成依据

- 你能用自己的话连接数据发送、保存与网页读取，说明必要角色的职责。
- 你能解释三种中断为什么可能产生不同的现象。
- 你能区分已查到的事实、自己的推断和暂时不知道的部分。

是否掌握由你的解释和后续观察决定；生成文档、抄写拓扑或看到旧验收 `passed` 都不自动算完成。本轮不启停 VM、不改配置、不注入故障。
